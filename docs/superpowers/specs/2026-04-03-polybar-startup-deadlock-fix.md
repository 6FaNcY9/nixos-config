# Polybar Startup Deadlock Fix

**Date:** 2026-04-03
**Status:** Approved

## Problem

After every login, the desktop (polybar, i3 keybindings) does not appear for ~90 seconds. The only known workarounds are:

- Wait ~90 seconds (systemd timeout expires, unblocking the chain)
- Run `nixos-rebuild switch` from TTY (forces `systemctl --user daemon-reexec`, killing the blocked D-Bus wait)

## Root Cause

A circular dependency deadlock in the session startup sequence.

### Startup chain

`~/.xsession` (generated by Home Manager for `xsession.windowManager.i3`) runs:

```bash
systemctl --user start hm-graphical-session.target   # ← BLOCKS
exec i3
```

The `systemctl start hm-graphical-session.target` call is **synchronous**. It blocks until `hm-graphical-session.target` is fully active. The activation chain is:

```
hm-graphical-session.target  (After=tray.target)
  └── tray.target             (After=polybar.service, Wants=polybar.service)
        └── polybar.service   (Type=forking — active only when start script exits)
              └── polybar-start script loops:
                    until I3SOCK=$(i3 --get-socketpath); do sleep 0.5; done
```

### The deadlock

- `polybar-start` loops waiting for the i3 socket
- i3 hasn't started because it's the **next line** in `~/.xsession` after the blocking `systemctl start` call
- `systemctl start` can't return because `polybar.service` (Type=forking) hasn't forked yet
- `polybar.service` can't fork because it's waiting for i3
- i3 can't start because `systemctl start` hasn't returned yet

**Resolution today:** After 90 seconds (`DefaultTimeoutStartSec`), systemd times out the `polybar.service` start job and marks it failed. `tray.target` becomes active anyway (Wants= tolerates failure). `hm-graphical-session.target` completes. `systemctl` returns. `~/.xsession` runs i3. i3 creates its socket. polybar restarts via `Restart=on-failure` and finds the socket immediately.

### Evidence

Journal from 2026-04-03, second login session:

```
09:01:22  xsession-wrapper starts (bash pid 2080)
09:01:22  "Starting Polybar status bar..."
09:02:19  User runs nixos-rebuild switch from TTY2
09:02:43  systemd[2033]: Reexecution requested... (switch-to-configuration)
09:02:43  systemctl[2104]: D-Bus connection terminated while waiting for jobs.
09:02:43  i3 started (pid 3173)
09:02:43  polybar started (pid 3217)
```

The rebuild caused daemon-reexec which killed the D-Bus wait → `systemctl start` returned early → i3 and polybar appeared at the same instant.

## Fix

Two changes to `home-modules/features/desktop/polybar/default.nix`.

### 1. Change script: `&` → `exec`

```bash
# Before
polybar --reload top &

# After
exec polybar --reload top
```

The `exec` replaces the shell process with polybar directly. The wait loop still runs first, but the service type change (below) means systemd no longer waits for it to complete before considering the service active.

### 2. Override service type: `forking` → `simple`

```nix
systemd.user.services.polybar.Service.Type = lib.mkForce "simple";
```

`Type=simple` declares the service active the instant `ExecStart` is launched — not when it forks. This means:

- `systemctl start polybar.service` returns immediately
- `tray.target` is satisfied immediately
- `hm-graphical-session.target` completes immediately
- `~/.xsession` runs `i3` within milliseconds of login
- The polybar start script (now the live service process) finds the i3 socket in a few seconds and `exec`s polybar

### Expected result

Desktop appears in ~3–5 seconds after login (time for i3 to initialise and create its socket) instead of ~90 seconds.

### Behaviour after fix

| Event | Timing |
|---|---|
| Login | T+0s |
| `systemctl start hm-graphical-session.target` | T+0s (returns immediately) |
| i3 launched by xsession | T+0s |
| i3 socket created | T+3–5s |
| polybar wait loop exits, execs polybar | T+3–5s |
| Desktop visible | T+3–5s |

### `Restart=on-failure` still works

If polybar crashes after startup, systemd restarts `polybar.service`. The start script re-runs, waits for the i3 socket (i3 is already running so this returns immediately), and `exec`s polybar again.

## Files Changed

| File | Change |
|---|---|
| `home-modules/features/desktop/polybar/default.nix` | Script `&` → `exec`; add `systemd.user.services.polybar.Service.Type = lib.mkForce "simple"` |
